# Release v0.1.2

Release date: 2026-11-09 (release PR merged; tag pending the owner's step).

This release is the first tagged version of the repository. Its changelog section is in
[projects/axiom/CHANGELOG.md](../../projects/axiom/CHANGELOG.md#011---2026-11-08). The
release process is in [docs/engineering/release-process.md](../engineering/release-process.md).

## What is in it

### Axiom simulation (crate `axiom`)

- **Simulation core (milestone 1):** belt lanes in fixed-capacity ring buffers, a round-robin
  splitter, an inserter state machine, and a 32 by 32 chunk grid with sleep and wake.
- **WASM export layer:** the C-ABI functions the browser loads, including a snapshot of items on
  the belts for drawing.
- **Browser item feed:** the simulation runs in a Web Worker at 60 Hz. Press `F` to feed one item
  onto the head of the chain. Items are drawn each frame.
- **Governance:** CI gates for formatting, clippy, tests on three operating systems, coverage,
  benchmark smoke, WASM build, supply chain, and Markdown. Also the ADRs and Conventional Commits
  rules.

Version choice: the item feed was added after the `0.1.2` version was set and before its tag. It
is folded into `0.1.2`, not released as `0.2.0`, because no tag existed yet. The pre-1.0 policy
allows this.

### Tic-tac-toe (`projects/tictactoe`)

A new project in the monorepo. It is not part of the axiom crate, so its code has no changelog
section here. It is recorded in this document only.

- **Rules core (Rust):** turns, wins, draws, and rejected moves, with 19 tests.
- **Web front end:** a 3 by 3 board with screen-reader labels, a live status line, a reset button,
  and text kept in a separate translation file. The Rust code is built to WebAssembly by CI.
- **Win line:** drawn across the winning cells, cleared by Reset.
- **Studio docs:** six team roles with their handoffs, the colour palette with contrast ratios,
  the icon spec, and the grid rules (`docs/studio/`).

Not in this release: Android and iOS builds (deferred), the icon image files, and the tic-tac-toe
`Cargo.lock`, which needs a commit from a machine that can reach crates.io.

## Checks

- `make release-check` confirms the Cargo version, the tag name, and the changelog section agree.
- CI on the release pull request must be green before the merge.
- The release job checks SHA256 sums, creates the attestation, and publishes the GitHub release.
